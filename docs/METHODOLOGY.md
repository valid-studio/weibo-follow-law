# 特征名单筛选与权重计算方法论 (Methodology)

本文档系统说明「微博关注列表定律」扩展内置打分引擎（[`shared/radar_engine.js`](../shared/radar_engine.js)）背后的统计建模原理、去热门校准方法及多层次防误伤机制，并提供纯 Python 标准库参考脚本 [`scripts/calc_weights.py`](../scripts/calc_weights.py) 供社区审计与独立复现。

> **隐私与脱敏声明**：本文档及配套脚本仅阐述通用的统计数学模型与算法参数，不包含任何个人用户数据、私有群组信息、原始采样名单或任何非公开账号标识。

---

## 背景与理论基础

「关注列表定律」概念源自微博博主 `@tombkeeper` 的长期观察与系统总结（涵盖归纳法与演绎法交互迭代、非对称污染模型、清粉与拉黑降噪等实战思路），其核心脉络已整理于 2026-07-24 发布的汇总原帖：[《关注列表定律合辑》](https://weibo.com/1401527553/Ra8WyguDC)。

本扩展及本文档所述模型是基于上述思路以**工程化**与**统计学去偏**方式实现的本地化浏览器工具：在保留“通过公开关注样本结构识别信息输入倾向”直觉的前提下，进一步引入双样本对照组基线、高粉丝大众号去热门惩罚、板块边际递减封顶、总关注数阻尼与共同关注免计分等机制，以适配日常浏览中的低误伤辅助决策。

---

## 一、观测前提与双样本对比框架

### 1.1 最近窗口观测效应
平台关注列表分页接口通常按关注时间倒序返回用户**最近新关注的约 140～200 位账号**（对应扩展参数 `followScanMaxPages`，每页约 20 条：宽松档 7 页、标准档 9 页、严格档 10 页）。因此，关注列表特征本质上反映的是用户在**近期活跃信息输入窗口**中的结构性偏好，而非终身全量关注档案。

### 1.2 双样本统计对比设计（Target vs Baseline）
特征筛选采用经典的有监督对比抽样框架，所有样本均经严格去标识化处理后再进入聚合统计：

1. **目标观察样本组（Target Group，$N_T$）**：关注列表公开可见、且在公共讨论中呈现典型同质化/高强度情绪输出特征的匿名抽样账号集合。
2. **普通日常对照组（Baseline Group，$N_B$）**：跨领域（科技、财经、生活兴趣、全网公开热门评论区等）广泛抽样的普通活跃账号集合。

> **为什么对照组不能局限在单一圈层？**  
> 如果对照组仅来自某个垂直兴趣圈（例如几乎不关注财经资讯的技术圈账号），则大众短线股评号、泛娱乐或热门科普大V在对照组中的出现率会被人为低估，进而导致普通股民或大众新闻读者在真实大盘下被误判。只有采用覆盖多元普通网民的对照组，才能剥离全网背景噪声。

## 二、如何从样本中筛出特征名单

对每位候选被关注博主 $i$（以 UID 为主键，并将已知关联小号/曾用名归并至同一实体），分别统计其在最近 ~200 关注窗口内被目标组关注的独立人数 $c_{T,i}$ 与被对照组关注的独立人数 $c_{B,i}$：

1. **最小支持度过滤（Minimum Support）**  
   要求候选博主在目标组中达到最小出现频次门槛（例如 $c_{T,i} \ge c_{\min}$，且目标组覆盖率达到最低下限），直接剔除仅在极个别账号中偶发出现的噪声。
2. **对照组低基线与净富集筛选（Net Enrichment Filter）**  
   计算目标组与对照组（经后文双源校准后）的净富集差值：
   $$\Delta p_i = p_{T,i} - p_{B,i}^{\text{eff}}$$
   仅当 $\Delta p_i > \Delta p_{\min}$ 且对数优势比显著大于 0 时，才保留为有效区分特征；目标组与对照组占比相近或对照组更高的账号，不具备区分能力。
3. **生态板块归类（6 大领域）**  
   通过筛选的内置参考特征账号（当前引擎内置 72 组特征实体）按内容主题归入 6 个互不重叠的板块：
   - `politics`：时政与国际话题
   - `social`：情感锐评与热门大V
   - `tech_acg`：科技、科普与二次元
   - `stock`：短线炒股资讯号
   - `military`：军事与防务话题
   - `overseas`：海外猎奇与暗黑叙事

## 三、热度与公共账号去偏（`DEFAULT_BASELINE_EXCLUSIONS`）

在统计交叉表时，经常会发现一些全网普及率极高的账号在目标组中也频繁出现（例如 15%～25%），但在普通对照组中出现率同样高达 30%～80%。这类账号分为三类：

1. **平台功能与新手引导号**：如红包助手、客服、会员提醒、热搜/文章服务号等；
2. **国民级官方大众媒体**：主流央媒、综合性新闻客户端官微等；
3. **大众公共科普与全网高知名意见领袖**：跨圈层日常关注基数极大的一般科技、财经或公共评论账号。

**处理原则**：这类账号的流行源于平台默认曝光与通用实用价值，**信息增益为零甚至为负**，不能作为倾向性判别特征。因此引擎将其直接归入 [`DEFAULT_BASELINE_EXCLUSIONS`](../shared/radar_engine.js)（基线排除名单）：

- 在 `evaluateFollowing()` 匹配开始前，优先将命中 `baselineExclusions`（支持归一化昵称与 UID）的账号剔除并计入 `excludedCount`；
- 用户可在扩展「偏好与规则」设置页中随时查看或增删自定义排除名单。

## 四、单个博主权重 $w_i$ 如何计算（双源校准 + 去热门惩罚）

为同时克服**有限对照组抽样方差**与**高粉丝大众号流行度偏差**，单个特征博主的权重 $w_i$ 采用「对照组实测关注率 + 粉丝基盘幂律下界」双源校准的对数优势比（Log-Odds Ratio）模型：

### 4.1 平滑样本关注率
采用平滑参数 $\alpha$（如 Jeffreys 先验 $\alpha = 0.5$）避免零频次导致对数发散：

$$p_{T,i} = \frac{c_{T,i} + \alpha}{N_T + 2\alpha}, \qquad p_{B,i}^{\text{obs}} = \frac{c_{B,i} + \alpha}{N_B + 2\alpha}$$

### 4.2 粉丝基盘幂律下界（高粉丝去热门惩罚）
百人规模的对照组仍可能因为抽样偶然性，漏掉某些数百万乃至上千万粉丝的超级大V（使 $c_{B,i}=0$）。为此引入基于粉丝量 $F_i$ 的次线性幂律下界作为先验背景基线：

$$p_{B,i}^{\text{pop}} = \min\!\left(p_{\text{cap}},\ \max\!\left(p_{\min},\ c_0 \cdot \left(\frac{\max(F_i, F_0)}{F_{\text{ref}}}\right)^{\gamma}\right)\right)$$

其中 $0 < \gamma < 1$ 刻画粉丝总量向普通活跃用户渗透率的次线性增长规律。取实测值与先验下界的最大值作为有效对照组基线：

$$p_{B,i}^{\text{eff}} = \max\!\left(p_{B,i}^{\text{obs}},\ p_{B,i}^{\text{pop}}\right)$$

### 4.3 对数优势比与权重映射
基于有效基线 $p_{B,i}^{\text{eff}}$ 计算对数优势比（LOR）：

$$\text{LOR}_i = \ln\!\left(\frac{p_{T,i}}{1 - p_{T,i}}\right) - \ln\!\left(\frac{p_{B,i}^{\text{eff}}}{1 - p_{B,i}^{\text{eff}}}\right)$$

再结合支持度平滑缩放系数 $k$ 与安全上界截断，得到最终静态权重 $w_i$（内置特征矩阵权重分布在 `0.12` ～ `1.45`）：

- **高特异度垂直特征号**（目标组高频、对照组极低且非千万粉泛媒体）：$w_i \in [1.00,\ 1.45]$；
- **破圈热门大V / 千万粉媒体号**（受 $p_{B,i}^{\text{pop}}$ 或 $p_{B,i}^{\text{obs}}$ 强惩罚）：$w_i \in [0.15,\ 0.80]$；
- **普通大众高频炒股号**（对照组有一定自然基线）：$w_i \in [0.12,\ 0.35]$。

> **单人安全保障**：由于最大单博主权重为 `1.45`，远低于标准档轻度预警线 `3.1`，**仅关注 1～2 位任意热门或特征博主永远不会触发预警**。

## 五、单用户得分汇总与五重防误伤机制

在扩展本地执行评估时，`evaluateFollowing()`（详见 [`shared/radar_engine.js`](../shared/radar_engine.js)）严格按以下 5 个阶段计算最终得分与展示级别：

### 5.1 四重自动豁免与共同关注免计分
除非用户主动点击「🧪 模拟访客自测」（`simulateVisitor: true`），否则以下对象自动豁免：
1. **登录用户本人豁免**（`exemptReason = "self"`）；
2. **官方蓝V机构号豁免**（`verifiedType` $\in [1, 7]$ 的政务、媒体、企业等机构认证账号，`exemptReason = "org_verified"`）；
3. **本人已关注 / 互关博主豁免**（开启 `exemptFollowedUsers` 时对已关注对象免除预警，`exemptReason = "following"`）；
4. **共同关注特征免计分**：若被检测用户关注的某特征号恰好也是当前登录用户本人关注的账号，该项在明细中保留展示并标注「共同关注(免计分)」，其计分权重强制置为 `effectiveWeight = 0`。

### 5.2 板块内边际递减与炒股板块硬封顶
对所有 `effectiveWeight > 0` 的命中特征按所属板块分组，并在板块内按权重从高到低排序 $w_{(0)} \ge w_{(1)} \ge \dots$：

- **短线炒股板块（`stock`）**：
  - 排名乘数为 `[1.0, 0.60, 0.35]`，第 4 位及以后为 `0.20`；
  - 板块累计得分实施硬封顶：
    $$S_{\text{stock}} = \min\!\left(0.70,\ \sum_{k \ge 0} w_{(k)} \cdot m_k^{\text{stock}}\right)$$
    （即使关注全部 8 个短线股评号，炒股板块总贡献也绝不超过 `0.70`。）
- **其余 5 个板块**（`politics`、`social`、`tech_acg`、`military`、`overseas`）：
  - 排名乘数为：前 2 位 `1.0`，第 3 位 `0.82`，第 4 位及以后 `0.65`；
  - 按单账号原始有效权重是否 $\ge 0.85$ 分流至**核心锚点池（$S_{\text{core}}$）**与**泛话题池（$S_{\text{pan}}$）**：
    $$S_{\text{core}} = \sum_{w_{(k)} \ge 0.85} w_{(k)} \cdot m_k, \qquad S_{\text{pan}} = \sum_{w_{(k)} < 0.85} w_{(k)} \cdot m_k$$

### 5.3 泛话题层凹函数饱和（防共线性堆叠）
多个低权重泛话题号与股评号往往共享“平台热门信息流推荐”这一潜在共线性因子，不能线性叠加。引擎对泛话题总池施加对数凹函数饱和压缩：

$$S_{\text{pan,eff}} = 1.85 \cdot \ln\!\left(1 + \frac{S_{\text{pan}} + S_{\text{stock}}}{1.85}\right)$$

$$\text{rawScore} = S_{\text{core}} + S_{\text{pan,eff}}$$

### 5.4 总关注数对数阻尼（高关注样本公平校准）
一个人如果总关注了 3,000 人，其最近 200 关注或随机碰撞到 2 个泛热门号的概率自然高于只关注 150 人的账号。引擎依据被检账号的公开总关注数 `friendsCount`（不小于实际扫描数 `scannedCount`）计算阻尼分母：

$$\text{denom} = 1 + 0.28 \cdot \max\!\left(0,\ \ln\!\left(\frac{\max(\text{friendsCount},\ 150)}{350}\right)\right)$$

$$\text{score} = \frac{\text{rawScore}}{\text{denom}}$$

当 `friendsCount <= 350` 时 `denom = 1.0`；当 `friendsCount = 1,000` 时 `denom ≈ 1.29`；当 `friendsCount = 6,600` 时 `denom ≈ 1.82`。

### 5.5 特异度门控、阈值分级与后验概率映射
1. **特异度门控（Specificity Gate）**：  
   若非炒股命中项的最大权重 `< 0.78` 且命中的非炒股板块数 `< 3`，则强制将得分钳制在预警线之下：
   $$\text{score} \leftarrow \min(\text{score},\ \max(0,\ \text{warnThreshold} - 0.15))$$
   从而保证纯股民或仅涉猎 1～2 个大众泛话题的普通用户绝不会跨越预警线。
2. **三档敏感度预设（`SENSITIVITY_PRESETS`）**：

| 档位 | `warnThreshold`（轻度倾向） | `highThreshold`（高度匹配） | `followScanMaxPages`（扫描深度） |
| :--- | :---: | :---: | :---: |
| `loose`（宽松） | `3.9` | `5.6` | `7` 页（约 140 关注） |
| `standard`（标准 · 默认） | `3.1` | `4.7` | `9` 页（约 180 关注） |
| `strict`（严格） | `2.5` | `4.1` | `10` 页（约 200 关注） |

3. **分级输出与行内静默**：
   - `score >= highThreshold` $\rightarrow$ `level = "high"`
   - `warnThreshold <= score < highThreshold` $\rightarrow$ `level = "warn"`
   - `0 < score < warnThreshold` $\rightarrow$ `level = "low"`（**行内 100% 静默不贴徽章，不展示惊吓式百分比**）
   - 无有效命中或已豁免 $\rightarrow$ `level = "none"`
4. **Logistic 概率映射（仅用于达到参考线的参考提示）**：
   $$P(\text{score}) = \text{clamp}\!\left(\text{round}\!\left(\frac{100}{1 + e^{-1.35(\text{score} - 2.95)}}\right),\ 1,\ 99\right)$$

## 六、使用通用脚本复现校准流程

仓库内置了零第三方依赖的 Python 3 参考脚本 [`scripts/calc_weights.py`](../scripts/calc_weights.py)，支持直接运行虚拟脱敏样本演示或输入您自己的匿名化 JSON 数据集进行权重计算与得分验证：

```bash
# 1. 运行内置纯虚构脱敏样本演示（筛选 + 双源权重校准 + 防误伤评估验证）
python3 scripts/calc_weights.py --demo

# 2. 对自定义匿名化 JSON 数据集计算特征权重与基线排除建议
python3 scripts/calc_weights.py --input path/to/anonymized_samples.json --output weights_out.json
```

脚本输入格式、可调校准参数及演示输出详见 [`scripts/calc_weights.py`](../scripts/calc_weights.py) 顶部注释与 `--help` 说明。
